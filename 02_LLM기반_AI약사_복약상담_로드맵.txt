문서 2. LLM 기반 AI 약사·복약 상담 기능 로드맵 수립
프로젝트: 알콩약콩 (alkong_yakong)

--------------------------------------------------------------------------------
0. 이 기능은 사용자를 위해 무엇을 하는가 (최종 목적)
--------------------------------------------------------------------------------

어르신이 "이 약 뭐야?", "어떻게 먹어?", "주의할 점은?" 을
어려운 설명서 대신 **쉬운 말**로 물어볼 수 있게 한다.

  사용자가 얻는 것
  - 약 이름을 대충/오타로 쳐도 후보를 골라 줌 (아산형 자동완성)
  - 식약처·허가정보 등 **공식 자료에 근거한** 답
  - 긴 전문용어 대신 짧은 어르신용 문장
  - 오늘 먹는 약·처방 등록 약과 이어지는 상담

  한 줄: "물어보면, 공식 자료 바탕으로 쉽게 알려 주는 AI 약사"


--------------------------------------------------------------------------------
1. 텍스트 벤다이어그램 (세 원이 겹치는 구조)
--------------------------------------------------------------------------------

  AI 약사 기능은 아래 세 영역이 겹쳐야 "안전한 상담"이 된다.

              A. 질문·자동완성
           (앱 채팅 / suggestions)
           _______________
          /               \
         /  약이름 입력·선택 \
        |  FAQ·초성·오늘약   |
         \        _________/__________
          \      /   ★공통   \         \
           \    / 확정된 약이름  \  C 쉬운답 \
            \  / + 공식 source  \  생성·가드\
             \/____________________\______\
             /                      \
            /   B. 검색·확정          \
           |  spell→match→retrieve    |
            \  허가DB / e약은요      /
             \______________________/


  [A] 질문·자동완성 ─── 사용자가 친 말, 후보 칩
  [B] 검색·확정 ─────── 오타 교정·공식 약 찾기
  [C] 쉬운 답 ────────── 고정DB답 / LLM생성 / 가드

  ★ 겹치는 핵심 (A∩B∩C)
  - "이 질문에 쓸 공식 약 1개 + 근거 문장"이
    들어와 → 검색으로 확정되고 → 쉬운 말로 나간다.
  - 공식 자료가 없으면 LLM이 마음대로 지어내지 않는다.


--------------------------------------------------------------------------------
2. 어디서 들어오고 어디로 나가는가 (입·출력)
--------------------------------------------------------------------------------

[IN — 들어옴]
  ① 자동완성
     GET /api/v1/drug-explain/suggestions?q=&user_id=
     - 입력 글자, 초성, 오늘 약, 허가DB 후보, FAQ 힌트

  ② 채팅 질문
     POST /api/v1/drug-explain/chat
     body: { user_id, message }
     - 예: "타이레놀 뭐에 좋아?"
            "타일레놀" (오타)
            "아스피린 부작용"

[처리 — chat_pipeline 단계]
  stage spell    : 문장에서 약 이름 후보만 추출 (지어내지 않음)
  stage match    : name_matcher
                   ≥0.90 자동확정 / 0.75~0.90 후보칩 반환
  stage retrieve : retrieve_official
                   1) mfds_drug_permission.db
                   2) alkongyakong.db medicines
                   3) e약은요 API
  stage fixed    : FAQ 종류면 DB 필드 기반 고정 답
  stage generate : 고정 답이 애매할 때만 Gemini로 쉬운 말 생성
                   (반드시 source_text 근거)
  stage guard    : 근거와 안 겹치는 문장 삭제
  stage excerpt  : 그래도 실패 시 공식 원문 발췌

[OUT — 나감]
  {
    ok, reply,
    candidates?  (애매할 때 "혹시 이 약인가요?" 칩),
    trace        (original, corrected, source, stage …)
  }
  → Flutter 약 설명/채팅 화면


--------------------------------------------------------------------------------
3. DB·외부는 어떤 쿼리/호출을 쓰는가
--------------------------------------------------------------------------------

사용 저장소
  - alkongyakong.db
  - mfds_drug_permission.db
  - easy_category_map.db   (쉬운 괄호 분류·chat_links)
  - 식약처 e약은요 API     (실시간 보조)

주요 호출

  (1) 자동완성 suggestions
      - 허가DB 제품명 검색 (search_permission_names 등)
      - SELECT … FROM medicines / user_medicines (오늘·등록 약)
      - easy_category_map.db
          SELECT trigger, link_type, link_value FROM chat_links …
          SELECT official_phrase, easy_label … FROM category_map …

  (2) 약 이름 매칭 lexicon
      - suggestions 결과 label 목록을 사전으로 사용
      - match_medicine_name(query, lexicon)

  (3) 공식 자료 retrieve_official
      - mfds_drug_permission.db 제품·상세
      - SELECT * FROM medicines WHERE product_name IS NOT NULL
      - e약은요 search_drug_info_by_name(...)

  (4) 쉬운 분류
      - SELECT … FROM category_map (easy_category_map.db)
      - 표시명: "약이름 (열나약)" 형태

  (5) LLM (Gemini)
      - generate_from_source(question, official)
      - 입력: 사용자 질문 + source_text만
      - 출력: 짧은 쉬운 문장 (최대 문장 수·길이 제한)

  (6) 가드
      - guard_reply(draft, source_text)  ※ DB 아님, 문자열 근거 검사


--------------------------------------------------------------------------------
4. 로드맵 (현재 → 다음)
--------------------------------------------------------------------------------

[현재 — 동작 중]
  □ 자동완성 (초성·오타 근접·오늘약·FAQ 힌트)
  □ spell → match → retrieve → fixed/generate → guard
  □ 후보칩 (75~90%) "혹시 이 약인가요?"
  □ 쉬운 분류 괄호 (easy_category_map.db)
  □ 점수(trace)는 내부용, 어르신 화면엔 숨김 방향
  □ OCR로 등록된 약 ↔ 채팅 lexicon 연결

[단기]
  □ 채팅 이력 저장 (user별 질문·답 DB)
  □ OCR 직후 "방금 등록한 약 물어보기" 딥링크
  □ 함께먹기(DUR) 결과와 채팅 문장 연결
  □ 서버 클라우드 배포 (PC 꺼도 상담 가능)

[중기]
  □ 보호자/어르신 역할별 말투·깊이 조절
  □ 음성 입력 → 같은 chat pipeline
  □ 복약 알람 시각에 "이 약 설명 다시 보기"

[장기]
  □ 상담 품질 평가(근거 점수·거절률) 대시보드
  □ 다국어·큰글씨 전용 응답 템플릿 고도화


--------------------------------------------------------------------------------
5. 단계별 입·출력을 글로 풀면
--------------------------------------------------------------------------------

  (1) 들어옴: 어르신 채팅 문장 / 자동완성 터치
  (2) 후보: "타일레놀" → [타이레놀정 …] 칩 또는 자동확정
  (3) 검색: 허가DB·로컬·e약은요에서 공식 설명문 확보
  (4) 답변: 고정문구 우선, 필요 시 LLM이 source만 보고 쉽게 말함
  (5) 가드: 근거에 없는 문장 삭제
  (6) 나감: 짧은 한국어 답 + (애매하면) 약 선택 칩


--------------------------------------------------------------------------------
6. 요약
--------------------------------------------------------------------------------

AI 약사 = (질문·자동완성) ∩ (공식약 확정) ∩ (쉬운·가드된 답)

최종적으로 사용자에게:
  "약 이름을 잘 몰라도, 공식 자료를 쉽게 물어보고 이해할 수 있다."
