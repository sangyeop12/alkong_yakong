--------------------------------------------------------------------------------
0. 이 기능은 사용자를 위해 무엇을 하는가 (최종 목적)
--------------------------------------------------------------------------------

약 정보는 틀리면 위험하다.
그래서 AI가 **없는 말을 지어내지 않게** 하고,
어르신이 **철자를 틀려도** 약을 찾을 수 있게 하며,
답은 **짧고 쉬운 말**로만 들리게 한다.

  사용자가 얻는 것
  - "AI가 지어낸 용량/부작용"에 속지 않음
  - "타일레놀"처럼 쳐도 타이레놀로 이어짐
  - 긴 허가문 대신 2~3문장 쉬운 설명
  - 애매하면 "이 약 맞나요?"로 고르게 함 (억지 확정 금지)

  한 줄: "틀리지 않게, 틀려도 찾아 주고, 쉽게 말해 준다."


--------------------------------------------------------------------------------
1. 텍스트 벤다이어그램 (세 원이 겹치는 구조)
--------------------------------------------------------------------------------

  안전한 어르신용 답변 = 아래 세 요구가 동시에 만족될 때.

              A. 환각 방지
           (근거 없는 문장 금지)
           _______________
          /               \
         /  source만 사용   \
        |  guard / filter    |
         \        _________/__________
          \      /   ★공통   \         \
           \    / 믿을 수 있는  \  C 쉬운말 \
            \  / 짧은 공식근거답 \  응답규칙\
             \/____________________\______\
             /                      \
            /   B. 오타·이름 교정     \
           |  spell / matcher / 후보칩 |
            \  0.90확정·0.75후보     /
             \______________________/


  [A] 환각 방지 ───── OCR filter, chat guard, retrieve 필수
  [B] 오타 교정 ───── spell 후보, fuzzy match, suggestions
  [C] 쉬운 언어 ───── 문장 수·길이 제한, easy_category, 고정답

  ★ 겹치는 핵심 (A∩B∩C)
  - "교정된 공식 약이름" + "근거 문장만 남긴 쉬운 답"
  - 셋 중 하나라도 빠지면:
      A 없음 → 거짓 정보 위험
      B 없음 → 약을 못 찾음 / 엉뚱한 약
      C 없음 → 어르신이 이해를 못 함


--------------------------------------------------------------------------------
2. 요구사항 정의 (Shall)
--------------------------------------------------------------------------------

■ R1. 환각 방지 (Hallucination Guard)

  R1-1 채팅 답변은 반드시 retrieve된 official.source_text 에 근거한다.
  R1-2 LLM 초안은 guard_reply 를 통과한 문장만 사용자에게 보여 준다.
       - 문장 단위로 source와 겹침(overlap) 검사
       - 답에만 있는 숫자(용량 등)가 source에 없으면 그 문장 폐기
  R1-3 공식 자료를 못 찾으면 "공식 자료에서 그 약을 찾지 못했어요"로
       끝내고, LLM이 추측 생성하지 않는다.
  R1-4 OCR 구조화도 filter_to_source 로
       원문(raw_text)에 없는 약이름·횟수·일수를 버린다.
  R1-5 고정 DB 답(효능/용법/주의 필드)을 LLM보다 우선한다.
  R1-6 가드 실패 시 공식 원문 발췌(excerpt) 또는 의사·약사 확인 안내.


■ R2. 오타·이름 교정 (Typo / Name Correction)

  R2-1 spell 단계는 약 이름 **후보만 추출**하고, 없는 약을 발명하지 않는다.
  R2-2 name_matcher
       - exact / 정규화 / 제형·mg 제거 / fuzzy 순
       - 유사도 ≥ 0.90 → 자동 확정
       - 0.75 ~ 0.90 → 자동 확정 금지, candidates 칩으로 선택 요청
       - < 0.75 → 매칭 실패 처리
  R2-3 suggestions 는 초성·부분문자열·오늘약·허가DB를 후보로 제시한다.
  R2-4 retrieve 는 허가정보 미러 → 로컬 medicines → e약은요 순으로
       공식명을 확정한다. (가벼운 fuzzy ≥ 0.80 보조)
  R2-5 OCR 매칭 실패 시에도 확인 화면용 임시코드(UNMATCHED)는 허용하되,
       uncertain 표시로 "확인 필요"를 알린다. (채팅의 공식답과는 구분)


■ R3. 쉬운 언어 응답 (Easy Language)

  R3-1 생성 답은 최대 문장 수·문장 길이 제한
       (validate_easy_output: 짧은 2~3문장 수준)
  R3-2 전문용어 나열보다 "무엇을 하는 약인지" 한 줄 요약을 우선한다.
  R3-3 easy_category_map.db 로 공식 표현 → 쉬운 괄호 분류
       예: 해열진통 → (열나약) 형태로 표시명에 붙일 수 있음
  R3-4 어르신 UI 카피는 "OCR 인식" 같은 기술 용어를 쓰지 않는다.
       ("처방전을 읽고 있어요", "이렇게 읽었어요")
  R3-5 내부 점수(evidence_score, name_match_score)는 기본 화면에 노출하지 않는다.
  R3-6 실패 메시지는 사용자를 탓하지 않는다.
       ("잘못 찍으신 게 아니니…", "다시 찍어드릴게요")


--------------------------------------------------------------------------------
3. 어디서 들어오고 어디로 나가는가
--------------------------------------------------------------------------------

[IN]
  - 채팅 message / suggestions q
  - OCR raw_text (구조화·필터 시)
  - official.source_text (가드·생성 시)
  - lexicon (오늘약·자동완성 후보)

[처리 모듈]
  A 환각방지
    - pharmacist/guard.py          guard_reply
    - ocr/parser.py                filter_to_source
    - pharmacist/chat_pipeline.py  fixed → generate → guard → excerpt
    - pharmacist/generate.py       apply_card_guard / validate_easy_output

  B 오타교정
    - pharmacist/spell.py          extract_drug_name_candidates
    - matching/name_matcher.py     AUTO_ACCEPT=0.90, CANDIDATE_MIN=0.75
    - pharmacist/suggestions.py    초성·fuzzy 후보
    - pharmacist/retrieve.py       허가DB fuzzy 보완

  C 쉬운언어
    - pharmacist/generate.py       쉬운 말 생성 + 길이 제한
    - pharmacist/easy_category*.py 쉬운 괄호
    - easy_category_map.db         category_map / chat_links
    - Flutter 시니어 카피·큰 글씨

[OUT]
  - 허용된 짧은 reply 문장
  - (애매 시) candidates[] 선택 칩
  - OCR items + uncertain 플래그
  - 거절 시 안전한 안내 문구


--------------------------------------------------------------------------------
4. DB·호출은 무엇을 보는가
--------------------------------------------------------------------------------

  (환각 방지 — 근거 확보)
    retrieve_official:
      mfds_drug_permission.db 제품/상세 조회
      SELECT * FROM medicines WHERE product_name IS NOT NULL
      e약은요 API
    → source_text 문자열을 가드의 "정답지"로 사용 (SQL이 아닌 텍스트 근거)

  (오타 교정 — 이름 사전)
    suggestions / lexicon 구성 시:
      허가DB 이름 검색
      user_medicines · medicines 조회
      easy_category_map.db
        SELECT official_phrase, easy_label … FROM category_map
        SELECT trigger, link_type, link_value FROM chat_links

  (쉬운 언어 — 분류·링크)
    lookup_easy_label / lookup_chat_links
    표시: format_display_name(이름, easy_category)

  (OCR 쪽 동일 철학)
    filter_to_source(parsed, raw_text)
    field_coverage 로 "칸을 채웠는지" 측정 (정답률과는 별개)


--------------------------------------------------------------------------------
5. 수용 기준 (Acceptance Criteria) — 예시
--------------------------------------------------------------------------------

  AC-1 "타이레놀 효능" → 공식 자료 있는 약이면 ok=true, 쉬운 2~3문장
  AC-2 "타일레놀" → 자동확정 또는 후보칩, 없는 약 이름 발명 없음
  AC-3 유사도 0.80대 → 반드시 사용자 선택 (자동 확정 금지)
  AC-4 존재하지 않는 약이름 → "공식 자료에서 찾지 못했어요" (추측 답 없음)
  AC-5 LLM이 source에 없는 용량을 쓰면 guard가 해당 문장 제거
  AC-6 OCR 표의 "| 0.50 | 3 | 7 |" → frequency/duration 유지 (표 필터)
  AC-7 화면 카피에 "OCR", "LLM", "confidence 87%" 같은 용어 비노출


--------------------------------------------------------------------------------
6. 세 요구가 빠질 때 위험
--------------------------------------------------------------------------------

  환각만 있고 오타교정 없음
    → 답을 안전하게 막아도, 약을 못 찾아 상담 자체가 실패

  오타교정만 있고 환각방지 없음
    → 약은 찾았는데 AI가 용량·부작용을 지어냄 (의료 위험)

  쉬운말만 있고 근거·교정 없음
    → 읽기 쉬운 거짓 정보 (가장 위험)


--------------------------------------------------------------------------------
7. 요약
--------------------------------------------------------------------------------

요구사항 삼각형:

        환각 방지
           /\
          /  \
         / ★답 \
        /______\
   오타 교정    쉬운 언어

최종적으로 사용자에게:
  "틀리게 말하지 않고, 철자가 틀려도 찾아 주며, 쉬운 말로 이해시킨다."
