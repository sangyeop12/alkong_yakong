알콩약콩 사용자 흐름 (화면 · 기능 · 끌어오는 정보)


0. 내 정보 등록
화면: 첫 실행, 회원가입, 내 정보

사용자가 이름, 생년월일, 성별, 연락처, (있으면) 임신 여부, 보호자 정보를 넣는다.

끌어오는 것 / 기능:
- 사용자 등록 API가 이 값을 사용자 DB에 저장한다. 이후 모든 약·심박·알림은 이 사용자 기준으로 묶인다.
- 보호자 정보는 보호자 API로 저장된다. 나중에 심박이 이상할 때 누구에게 알릴지 여기서 정해진다.
- 생년월일·임신 정보는 함께먹기(DUR)에서 연령·임부 주의 약을 걸러 내는 데 쓰인다.


1. 로그인 · 회원가입
화면: 로그인, 회원가입

이미 등록된 사용자로 들어가거나, 0번에서 만든 계정으로 가입을 마친다.

끌어오는 것 / 기능:
- 가입 시 위 사용자 API가 계정을 만든다.
- 로그인 후에는 오늘 약 목록, 처방전, 챗봇, 심박이 모두 그 사용자 ID로 조회된다.


2. 오늘 홈
화면: 오늘(환자 홈). 아래 탭은 오늘 / 기록 / 내 정보.
오른쪽 아래 말풍선: 약 상담(챗봇)을 언제든 연다.

사용자가 앱을 열면 “지금 드실 약”이 가장 크게 보인다. 아침·점심·저녁 중 해당 시간대 약, 먹었는지 여부, 처방전 찍기, 심박 보기가 여기 있다.

끌어오는 것 / 기능:
- 오늘 약 API(`GET .../today-medicines`)가 이미 등록된 복용약과 오늘 스케줄을 가져온다. 화면에 허가 이름, 짧은 분류, 쉬운 한 문장, 투약량(0.50 / 1알)이 채워진다. 제품 함량(200밀리그램)은 이름에만 남긴다.
- 약 이름을 누르면 내 약 상세(`GET .../medicines/{code}`)로 간다. 목 데이터(메트포르민·아스피린)는 쓰지 않는다.
- 등록된 약이 없으면 빈 안내와 처방전 찍기만 보인다.
- 대시보드 API가 있으면 그날의 복용·심박 요약도 같이 볼 수 있다.
- 「먹었어요」를 누르면 복용 기록 API가 그 시간대 약을 복용 완료로 남긴다. 홈의 체크와 기록 탭이 이 기록으로 바뀐다.
- 놓친 약은 미복용 처리 API로 표시된다.
- 말풍선은 챗봇 화면(아래 7번, `DrugExplainScreen`)과 같다. 처방전을 안 찍어도 홈에서 바로 약 이름을 물어 볼 수 있다.


2-1. 내 약 목록 · 상세
화면: 내 정보 → 내 약 목록, 약 자세히

끌어오는 것 / 기능:
- 목록 API(`GET .../medicines`)는 활성 약을 종류당 1행으로 준다. 오늘 차(아침·점심·저녁 중복)와 같은 쉬운말을 쓴다.
- 상세는 같은 생성기의 분류·한 문장·주의·복용(양·횟수)만 보여 준다. 허가 효능 원문과 Gemini 설명 카드는 이 화면에 넣지 않는다.
- 약이 없으면 처방전 찍기로 안내한다. 손으로 적기는 공식 품목코드가 있을 때만 `POST .../prescriptions/confirm`으로 등록한다.


3. 처방전 사진 찍기
화면: 처방전 등록, 촬영(카메라·앨범)

처방전 또는 약국 복약안내문을 찍거나 앨범에서 고른다.

끌어오는 것 / 기능:
- 사진은 따로 “업로드만 하는 API”가 없다. 찍은 이미지가 바로 다음 단계 인식 요청에 실려 간다.
- 이 화면의 역할은 인식에 쓸 원본을 고르는 것이다.


4. 글자 읽기
화면: 읽는 중

사진이 서버로 넘어가 글자를 뽑고, 약 줄로 나눈다.

끌어오는 것 / 기능:
- 처방전 인식 API가 사진을 받는다.
- 글자 인식(Gemini Vision, 안 되면 CLOVA OCR)이 사진 속 한글·숫자를 원문으로 옮긴다. 사용자가 보는 “읽는 중”은 이 작업이다.
- 서버가 원문에서 약 이름, 하루 몇 번, 며칠분을 골라 낸다. 표 머리글·금액·가짜 조각은 약으로 쓰지 않는다.
- 각 약 이름마다 식약처 의약품 제품 허가정보를 조회한다. 먼저 허가 DB에서 찾고, 없으면 식약처 허가 API를 짧게 부른다. 여기서 공식 제품명, 품목코드, 성분, 효능·주의 요약이 붙는다.
- 이 단계에서는 아직 복용 알림이 생기지 않는다. 미리보기만 만든다.


5. 인식 결과 확인
화면: 공식 약 확인(확인률 %), 이렇게 읽었어요(약 카드)

읽힌 공식 약 목록을 보여 준다. 맞으면 등록하고, 아니면 다시 찍는다.

끌어오는 것 / 기능:
- 화면의 약 이름·용량·횟수는 4번 인식 API 응답이다.
- 확인률은 “사진에서 약으로 본 것 중, 식약처 허가에서 공식 이름으로 맞춘 비율”이다. 성분이 빠졌다고 깎지 않는다.
- 「이대로 등록하기」는 등록 API를 부른다. 공식 품목코드가 있는 약만 복용약으로 넣고, 아침·점심·저녁 스케줄을 만든다. 그다음부터 오늘 홈에 약이 뜬다.
- 공식 목록에 없는 이름은 등록하지 않는다.
- 「다시 찍기」는 3번으로 돌아간다. 인식 API를 다시 탄다.


6. 함께먹기 확인
화면: 함께먹기(DUR) 안내

방금 등록했거나 이미 먹고 있는 약끼리, 같이 쓰면 안 되는 조합이 있는지 본다.

끌어오는 것 / 기능:
- 함께먹기 API가 사용자 약 목록(또는 방금 고른 약 코드)을 받는다.
- 식약처 DUR 자료(병용금기, 특정 연령·임부 주의 등, 서버가 미리 받아 둔 표)와 약의 성분을 맞춰 본다.
- 화면에 “이 약과 이 약은 같이 주의” 같은 결과가 나온다. 위험 조합이 있으면 강조하고, 해당 없으면 괜찮다는 안내가 나온다.
- 이 화면에서 약 상담(챗봇)으로 들어갈 수 있다. 챗봇은 7번과 같다.


7. 결과 보기 · 약 상담(챗봇)
화면: 함께먹기 안내 다음, 또는 홈 말풍선으로 연 AI 챗봇(약 상담)

약을 쉬운말로 설명하거나, “이 약 설명 / 같이 먹으면” 같은 질문을 받는다.

끌어오는 것 / 기능:
- 추천어 API가 입력 중인 글자와 오늘 약 이름을 받아, 약 이름·질문 후보를 자동완성에 띄운다. 식약처 허가 제품명 목록도 여기서 후보로 쓴다.
- 상담 API가 사용자가 고르거나 친 문장을 받는다.
- 약 이름을 공식 제품과 맞춘 뒤, 챗봇용으로 e약은요 자료를 끌어온다. 제품명, 성분, 효능, 복용법, 주의사항이 원문이 된다.
- Gemini는 그 원문만 근거로 어르신용 쉬운 문장을 만든다. 원문에 없는 효능·용량을 지어 내지 않는다.
- “같이 먹으면”이면 상담 API가 함께먹기(DUR) 결과를 다시 읽어, 주의 조합을 말로 풀어 준다.
- 특정 약 카드가 필요하면 약 설명 API가 같은 공식 자료로 설명 칸(효능, 복용, 주의, 보관)을 채운다.

중요: 챗봇은 7번 화면에만 있는 기능이 아니다. 2번 홈 말풍선에서도 같은 상담 API를 쓴다. 6번 함께먹기 화면에서도 들어간다.


8. Polar 착용 여부
화면: Polar 연결

약을 먹은 뒤 심박을 잴지 고른다.

끌어오는 것 / 기능:
- 이 단계 자체는 외부 약 API를 부르지 않는다. Polar 기기와 앱이 연결되는지만 본다.
- 안 함: 복용 기록만 남기고 12번으로 갈 수 있다.
- 함: 실시간 심박 화면으로 가서 9번을 한다.


9. 복용 후 심박수 측정
화면: 실시간 심박

약 먹은 뒤 Polar로 심박수를 잰다.

끌어오는 것 / 기능:
- 심박 API가 사용자, 분당 심박, 측정 시각, 기기 정보를 받는다.
- 서버가 심박 로그를 저장한다. 화면에 지금 심박수가 보인다.


10. 평소와 비교
화면: 심박 변화 확인

지금 심박이 그 사람의 평소 범위 안인지 본다.

끌어오는 것 / 기능:
- 같은 심박 API 안에서 처리된다. 별도 “변화율 전용 API”는 없다.
- 사용자에게 기준 심박이 없으면, 방금 잰 값을 기준으로 정상 범위(대략 그 값 아래·위)를 만든다.
- 이미 기준이 있으면 지금 BPM이 최저~최고 정상 범위 밖인지 비교한다.


11. 정상 / 이상
화면: 변화 판정(정상 / 이상), 알림

정상: 기록만 남긴다.
이상: 본인에게 알리고, 연결된 보호자에게도 알린다.

끌어오는 것 / 기능:
- 범위 밖이면 서버가 이상 사건(너무 낮음/너무 높음)을 저장한다. 기준과 차이가 크면 더 높은 주의로 표시한다.
- 보호자가 등록되어 있으면 알림을 남긴다. 보호자 홈에서 이상 심박을 볼 수 있다.
- 이상 목록 API가 지난 이상 기록을 다시 보여 준다.


12. 저장하고 홈으로
화면: 저장 완료, 오늘 홈, 기록 탭

처방전·복용·심박이 남은 뒤 오늘 홈으로 돌아온다.

끌어오는 것 / 기능:
- 처방 등록 API가 이미 넣은 복용약·스케줄이 오늘 약 API로 다시 읽혀 홈에 나타난다.
- 복용 기록 API로 남긴 “먹었어요”가 기록 탭에 날짜별로 쌓인다.
- 알림 생성 API가 있으면 다음 복용 시각에 맞춰 알림 목록을 만든다. 알림 조회 API로 그 목록을 본다.


화면과 끌어오는 정보의 짝 (흐름도 기준)

오늘 홈          ← 오늘 약 API, (선택) 대시보드 API, 복용 기록 API
처방전 촬영      ← 인식 API로 이어짐 (별도 업로드 API 없음)
읽는 중          ← 인식 API + 글자 인식(Gemini/CLOVA) + 식약처 제품 허가
인식 결과        ← 인식 API 응답, 등록 API
함께먹기         ← DUR API + 식약처 DUR 표
약 상담(챗봇)    ← 추천어 API, 상담 API, e약은요, Gemini, (같이 먹으면) DUR
실시간 심박      ← 심박 API
변화 판정        ← 심박 API 내부의 기준 비교, 이상 시 보호자 알림
기록 / 저장 완료 ← 복용 기록 API, 오늘 약 API, 알림 API


언제든: 2번 홈 말풍선으로 챗봇. 6번 함께먹기에서도 챗봇.
챗봇은 흐름에서 빠지지 않는다. 7번에만 있는 기능이 아니다.
